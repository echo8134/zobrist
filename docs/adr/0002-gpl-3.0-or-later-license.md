# License the project under GPL-3.0-or-later

## Context and Problem Statement

The core will link shakmaty 0.30.2, pgn-reader 0.29.1, and shakmaty-syzygy 0.28.1, all GPL-3.0-or-later with no linking exception. The repository is public. Which license can the project carry so that distributing a binary is lawful?

## Considered Options

* No license
* PolyForm Strict or Noncommercial
* GPL-3.0-or-later
* AGPL-3.0
* MIT and Apache-2.0 dual

## Decision Outcome

Chosen option: "GPL-3.0-or-later", because the FSF FAQ (IfLibraryIsGPL) says a distributed program linking a GPL library must be GPL as a whole, the MIT alternatives cozy-chess (last release 2024-04) and owlchess have no PGN reader, and the chess ecosystem (Stockfish, python-chess, En Croissant, ChessX, lichess as AGPL) is copyleft. No license and PolyForm are not GPL-compatible, so the combination could not be distributed. AGPL-3.0 is compatible, but its network clause adds nothing for a desktop app. MIT and Apache-2.0 cannot cover a binary that links a GPL library.

### Consequences

* Good, because every chess crate and the ecosystem fit without a fork.
* Bad, because the cargo-deny allow list must include GPL.
* Bad, because piece sets must be GPL-compatible. cburnett and merida (GPLv2+) and chessnut (Apache-2.0) are fine, alpha and the CC BY-NC sets are out.
* Neutral, because Stockfish runs as a separate UCI process, which the FSF FAQ (MereAggregation) treats as an aggregate. If it is ever bundled, ship the GPL text and a source pointer.

### Confirmation

`deny.toml` lists the allowed licenses and `cargo deny check` runs in `scripts/check.sh` and in CI. `LICENSE` holds the unmodified GPL-3.0 text.
